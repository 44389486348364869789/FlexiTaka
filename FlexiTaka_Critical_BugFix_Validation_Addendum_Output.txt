7. STRICT 11-DIGIT MOBILE NUMBER VALIDATION ARCHITECTURE
================================================================================
Every mobile number processed by FlexiTaka conforms to the standard Bangladesh telecom format:
- Format: Exactly 11 numeric digits starting with `01` (`01XXXXXXXXX`).
- Normalization Logic (`normalize_msisdn`):
  1. Trims leading and trailing whitespace.
  2. Strips spaces, dashes, parentheses, and plus signs.
  3. Strips country prefix `+88` or `88` if present.
  4. Validates length is exactly 11 characters.
  5. Validates structure against regex `^01\d{9}$`.
  6. Rejects any non-conforming input with HTTP 422 and code `INVALID_MOBILE_NUMBER`.
- Client-Side Enforcement:
  - `maxLength={11}` attribute on all mobile input HTML elements.
  - `onChange` filters any non-digit character (`e.target.value.replace(/\D/g, '')`).

9. LIVE BALANCE CHECK & CHUNKING ENGINE FIXES
================================================================================
- Live Balance Verification:
  - When creating a Cash Out order, `CashOutService` queries the customer's operator session.
  - Calls `adapter.get_balance(source_phone, session_data)`.
  - If `live_balance < requested_amount`, raises `ValidationException`:
    "আপনার SIM-এ পর্যাপ্ত ব্যালান্স নেই। বর্তমান ব্যালান্স: ৳X.XX (Insufficient SIM balance. Current balance: ৳X.XX)"
    with code `ErrorCode.INSUFFICIENT_BALANCE`.
  - Prevents order reservation, chunk plan generation, and receiving SIM usage.
- Chunking Calculation Fix:
  - Previous Behavior: A 50 BDT transfer was incorrectly assigned a chunk of 100 BDT.
  - Fixed Algorithm in `TransferEngine.calculate_chunks(amount_bdt, max_chunk_bdt)`:
    ```python
    chunks = []
    remaining = amount_bdt
    while remaining > 0:
        chunk = min(max_chunk_bdt, remaining)
        chunks.append(chunk)
        remaining -= chunk
    return chunks
    ```
  - Result: 50 BDT creates `[50]`, 101 BDT creates `[100, 1]`, 250 BDT creates `[100, 100, 50]`.
  - Telecom adapters updated to validate chunk amounts in range `1 <= chunk <= 100`.

10. TRANSFER STATE MACHINE, ERROR REPORTING & UI SYNCHRONIZATION
================================================================================
- New CashOutStatus States:
  - `TRANSFER_IN_PROGRESS`: Order is actively transferring balance chunks.
  - `TRANSFER_FAILED`: Chunk transfer encountered an unrecoverable telecom error.
  - `INSUFFICIENT_BALANCE`: SIM balance was depleted before or during transfer.
- State Transition Table (`CASHOUT_ALLOWED_TRANSITIONS`):
  - `WAITING_FOR_TRANSFER` -> `TRANSFER_IN_PROGRESS`, `TRANSFER_RECEIVED`, `UNDER_VERIFICATION`, `CANCELLED`
  - `TRANSFER_IN_PROGRESS` -> `TRANSFER_RECEIVED`, `TRANSFER_FAILED`, `INSUFFICIENT_BALANCE`, `UNDER_VERIFICATION`, `CANCELLED`
  - `TRANSFER_FAILED` -> `WAITING_FOR_TRANSFER`, `CANCELLED`
  - `INSUFFICIENT_BALANCE` -> `WAITING_FOR_TRANSFER`, `CANCELLED`
  - `TRANSFER_RECEIVED` -> `UNDER_VERIFICATION`, `APPROVED`, `CANCELLED`
  - `UNDER_VERIFICATION` -> `APPROVED`, `REJECTED`, `CANCELLED`
  - `APPROVED` -> `PAYOUT_PROCESSING`, `CANCELLED`

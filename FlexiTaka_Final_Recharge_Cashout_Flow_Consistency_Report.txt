This report documents the final resolution of the Recharge transaction flow bug,

All changes adhere strictly to the FlexiTaka Clean Architecture:
- Recipient number -> detect operator -> amount -> create recharge order
  -> show authoritative DB payment account (bKash/Nagad/Rocket/Bangla QR) + unique Order ID
  -> customer pays via MFS/banking app

  -> iPhone Shortcut POSTs SMS to https://flexitaka.online/api/gateway/verify-payment-ios-shortcut-method
  -> backend authenticates request & deduplicates TrxID
  -> exact order/amount match -> PAYMENT_VERIFIED -> automatic same-operator transfer engine.

2. CRITICAL RECHARGE OTP BUG FIX (ROOT CAUSE RESOLUTION)
--------------------------------------------------------------------------------
Issue:
The Recharge wizard page (/app/recharge) erroneously imported and triggered an
OTP verification modal using ZendSMS (api.requestOtp / /auth/request-otp),
blocking recharge order placement until the customer verified their phone.
This was incorrect because airtime recharge is an airtime top-up sent to any
recipient number—the customer does NOT need to verify ownership of the recipient SIM.

Root Causes Fixed:
1. Removed `import OtpVerificationModal from "@/components/OtpVerificationModal";`
2. Removed OTP component states: `verifiedPhone`, `otpModalOpen`, `otpSending`, `isPhoneVerified`.
3. Removed `handleTriggerOtp` and `handleOtpSuccess`.
4. Removed the OTP gate in `handleCreateOrder`:
   - OLD: `if (!isPhoneVerified) { await handleTriggerOtp(); return; }`
   - NEW: Entering operator, valid phone, and amount directly invokes `executeOrderCreation()`.
5. Removed the "OTP যাচাই করুন" / "Verify OTP" button and ShieldCheck icon from the recipient phone input field.
   - Replaced with a clean valid number indicator (`CheckCircle2` + "সঠিক নম্বর" / "Valid Number").
6. Removed `<OtpVerificationModal ... />` from the recharge page render tree.
7. Removed `REQUIRE_ORDER_OTP` check from `backend/app/modules/recharge/service.py`.
   - Recharge order creation never blocks on recipient phone verification.
8. Retained ZendSMS globally: ZendSMS remains active and intact for authentic user
   profile/auth login flows (/auth/request-otp and /auth/verify-otp).

9. IPHONE SHORTCUT SMS GATEWAY (PAYMENT VERIFICATION ENGINE)
--------------------------------------------------------------------------------
- Public URL: https://flexitaka.online/api/gateway/verify-payment-ios-shortcut-method
- Target: Apple iOS Shortcuts on FlexiTaka iPhone.
- Flow:
  1. Authenticates request using `X-Gateway-Secret` (`SHORTCUT_GATEWAY_SECRET`).
  2. Parses bKash / Nagad payment SMS (provider, transaction_id, amount_poisha, reference_code, sender_number).
  3. Replay Protection & Deduplication: checks `sms_transactions` collection.
     If TrxID was already processed, immediately rejects with `DUPLICATE_TRANSACTION`.
  4. Order Matching: matches pending recharge order by `order_id` in reference code and exact amount.
  5. Transitions order to `PAYMENT_VERIFIED` / `RECHARGE_PROCESSING`.
  6. Dispatches airtime transfer chunk via `TransferEngine` through operator retail SIM pool.

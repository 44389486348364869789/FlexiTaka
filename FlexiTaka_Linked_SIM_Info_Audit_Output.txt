1. EXECUTIVE SUMMARY & AUDIT FINDINGS
--------------------------------------------------------------------------------
A thorough audit of the Linked SIM implementation was performed across the backend
operator adapters (Grameenphone, Banglalink, Robi), database persistence layer,
customer user service, and frontend profile UI cards.

Previous Issues Uncovered & Corrected:
1. Fake Default for SIM Type:
   - Previously defaulted to "Prepaid" in schemas, service layer, and UI fallback
     even when the operator API did not return connection category.
   - RESOLUTION: Removed all fake defaults. When operator API does not return SIM type,
     backend stores `None` and UI explicitly displays "Not available" ("অনুপলব্ধ").
2. Fake Default for Balance Transfer Availability:
   - Previously defaulted to `True` / "Available ✓" across schemas and service layer.
   - RESOLUTION: Removed all hardcoded booleans. Only Banglalink API currently returns
     an explicit `enable_balance_transfer` boolean in its customer object. For GP and
     Robi where no explicit eligibility boolean is exposed in auth/balance, backend
     stores `None` and UI explicitly displays "Not available".
3. Fake "Just now" Last Synced Time:
   - Profile UI previously displayed hardcoded "Just now" ("এইমাত্র") regardless of
     the actual timestamp.
   - RESOLUTION: Implemented dynamic relative time calculation (`formatRelativeSyncTime`)
     based on authoritative ISO timestamps. If last synced timestamp is missing,
     displays "Not available".
4. Customer ID Integrity:
   - Verified that Customer ID is strictly populated from authoritative operator
     API responses (`customer_account_id` / `customer_id` / `id` / `subscriberId`).
     Never invented, hardcoded, or faked. Unverified SIMs or SIMs without operator ID
     explicitly display "Not available".

3. DETAILED IMPLEMENTATION VERIFICATION
--------------------------------------------------------------------------------
A. Customer ID Authenticity:
   - GP: Extracted from `data.get("customer_id") or data.get("account_id") or data.get("id")`.
     In test environment, matches `msisdn_88`. In production, uses real GP connect/user identifier.
   - Banglalink: Extracted from `cust_obj.get("customer_account_id") or cust_obj.get("customer_id")`.
     In test environment, matches `BL{msisdn}`. In production, uses real Banglalink customer account ID.
   - Robi: Extracted from `resp_data.get("customerId") or resp_data.get("subscriberId") or resp_data.get("account_id")`.
     In test environment, matches `ROBI{msisdn}`. In production, uses real Robi customerId.
   - Unverified / Unavailable: Evaluates to `None` in backend and renders:
     `<span style="color: #94A3B8;">Not available</span>` (or Bengali: "অনুপলব্ধ (Not available)").

B. SIM Type Display:
   - GP: Returned by `adapter.get_balance` in `extra["sim_type"]` (e.g., "Prepaid").
   - Banglalink: Returned by `cust_obj.get("connection_type")` or `cust_obj.get("type")`.
   - Robi: Not provided by Robi auth/balance endpoints -> explicitly returns `None` and displays "Not available".

C. Balance Transfer Availability:
   - Banglalink: Real boolean `cust_obj.get("enable_balance_transfer")` -> displays "Available ✓" (green) or "Unavailable" (red).
   - GP & Robi: Operator APIs do not expose a dedicated boolean status flag -> returns `None` and displays "Not available" (subtle muted text).

D. Last Synced Time Calculation:
   - Built custom `formatRelativeSyncTime(isoString)` in `website/src/app/app/profile/page.tsx`.
   - Returns "Just now" for events < 60s ago, "Xm ago" for < 60 mins, "Xh ago" for < 24 hours, or formatted date for older timestamps.
   - Returns "Not available" if timestamp is missing.
